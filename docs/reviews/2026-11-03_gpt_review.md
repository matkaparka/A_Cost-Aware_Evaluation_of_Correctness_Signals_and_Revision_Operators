# AI auto research 文件审阅

审阅日期：2026-11-03。对象：`CLAUDE.md`、`research_design.md`，以及目录中两份理论 TXT 和中文 DOCX 的相关论证。

**结论：这是一份有研究价值的方案草稿，尚不适合直接交给 AI 无人值守地运行完整确认性研究。** `CLAUDE.md` 的科研诚信和记录框架较好；`research_design.md` 的主要问题是理论与测量之间的推导、对照设计、统计功效和实现细节。修订后可以检验特定模型、任务、提示和更新规则下的纠错机制；目前不能据此验证整个动态回归理论、结构反身性的必要条件或 Lawvere 意义上的自我预测不可能性。

本次是设计与证据审查，没有运行模型实验、测试 GPU 环境或验证缺失的理论证明。下面的数值是独立的设计核算，不是实验结果；可由 `review_support/design_checks.py` 重算，输出在同目录的 `design_checks.json`。原有五个文件未作修改。

## 1. 已有的合理设计

- 将操作协议与研究设计分开，并规定冲突时的优先级。
- 设置开发集、预注册、偏离日志、失败报告、固定种子和运行登记。
- 同时报告 W→R 和 R→W，避免只看错误样本造成纠错能力虚高。
- 区分自然错误和注入错误，并计划配对比较。
- 意识到 frozen-only 实验不能直接研究参数更新，也限制意识、反身性和线性 probe 的结论强度。
- 先做本地基准，再决定云运行；设置预算、恢复机制和人工支出门槛。

这些应保留。需要补上的主要是把文字规范变成可检查的实验约束，以及明确什么结果真正支持、反驳或无法回答某项主张。

## 2. 在确认性实验前必须修正的问题

### 2.1 Claim 7 推不出目前的若干行为预测

位置：`research_design.md:15–19,37–44,52–55`；manifesto §11.1、§20 Claim 7。

“没有新增外部信息”不蕴含“不能提高准确率”。模型可以重算、搜索、重组已知信息，把原来答错的题算对。对于固定状态及与目标独立的随机数，数据处理不等式约束的是关于目标的互信息，不约束某个有限计算过程的答题准确率必须不升。

因此以下内容只能是额外的经验假设，不能当作 Claim 7 的直接推论：

- H1a：self-critique 相对 Wait 的增益应在 ±2pp 内。
- H1b：随机 verifier（p=0.5）不能带来正收益。即使其正确性信号不含信息，它仍可能改变模型的搜索路径、计算量和修改倾向。
- H2b：probe 认为正确的错误题不能被内部纠正。线性 probe 未读出的信息，后续非线性计算仍可能利用。
- H4b：自我更新的 spillover 平均非正。无新增外部信息的训练仍可能改善泛化。
- H4c：self-verdict 流必须漂移而 grounded 流必然稳定。具体更新规则、噪声、任务分布和正则化同样决定结果。

数学题还有更深的操作化问题：若 gold answer 是题目 q 的确定函数，则从理想 Shannon 视角给定完整 q 后，答案已无条件熵。verifier 对有限算力模型可以极有用，却不因此构成关于答案的新增条件互信息。必须区分“计算帮助”和“此前不可观测的世界信息”。

**建议：**把上述假设写成独立、允许失败的经验预测；在结论中只写它们是否成立。若要研究信息来源，增加一个隐藏随机状态的玩具任务：同一可见输入对应不同、对模型隐藏的随机世界状态，只有独立 verifier 能观察该状态。没有反馈的程序在平衡随机二元状态上期望准确率为 1/2；有反馈时再研究利用程度。这个任务能校验操作化和泄漏，仍不能用有限实验“证明 DPI”。

### 2.2 样本量不足以默认支持 ±2pp 等效性

位置：`research_design.md:34,71–73,142`。

每个数据集上限 500、测试占 80%，意味着通常至多 400 个独立测试题。设两个条件的配对正确性不同的比例为 d；真实均值差为零时，差值标准误近似为 √(d/n)。未作多重校正的 α=0.05 TOST 对应 90% CI。

| 假设的配对不一致率 d | n=400 时 90% CI 半宽 | 零效应下约 80% TOST 功效所需 n |
|---|---:|---:|
| 0.10 | 2.60pp | 2,141 |
| 0.20 | 3.68pp | 4,282 |
| 0.30 | 4.50pp | 6,423 |

这些是假设场景下的正态近似，不是对本模型的实测功效。所需 n 使用 `(z_0.95 + z_0.90)^2 d / 0.02^2`，未计 Holm、分层和估计方差的不确定性。即使把两个不同数据集合为 800 题，也不能自动解决问题，而且合并会改变目标总体。H2b 再取错误题中最高五分位时，若错误题约 200，仅余约 40 题；若五分位针对全体定义，错误子集还可能更少。

**建议：**用独立 pilot 的不一致率和效应范围做功效模拟，冻结样本量和有实质意义的 margin。预算不允许时，将 H1a 改为效应估计，结论写“证据不足”，不能把不显著写成等效，也不能看完 test 后扩大 margin。

### 2.3 Exp 1 尚未真正分离信息、触发和归属

位置：`research_design.md:78–94`。

条件计数 20 是正确的，但这是部分交叉设计，并非三个概念完全正交的 factorial。

- F0 已要求 review，自带修改触发；缺少保留 a0 的基准和等计算量的重新作答基准。
- F2 相对 F1 同时改变了文字、输出长度、计算量和生成阶段，不能直接解释为“控制 trigger 后的纯 critique 效应”。F2 是否同样包含 Wait 也未明确。
- own/external 同时改变聊天角色、包装文字、位置和指令。D-inj 放在 assistant 中是“被归属于模型的文本”，不一定真是该模型生成的文本。
- self-labeled verdict 放在先前 assistant turn，tool/user 放在后续消息，还改变了反馈时间与局部上下文。
- H1c 中“channel effect”没有定义：最大两两差、均方差、某一预定 contrast，还是 omnibus 效应？

实际模板尤为关键：当前 [Qwen3-4B tokenizer 配置](https://huggingface.co/Qwen/Qwen3-4B/blob/main/tokenizer_config.json) 将 tool 消息编码成 user 包装下的 `<tool_response>`，并对部分历史 assistant 内容中的 thinking 段作处理。因此 API 的 role 字段不是三个独立模型角色的保证，声称“相同文本”也必须在最终 token 序列上验证。

**建议：**保存每个条件渲染后的完整 prompt、token IDs、reviewed-solution span 和 feedback span；自动核对内容一致性。行为主实验固定位置、角色、计算预算，单独操纵 verifier 可靠性；trigger 与 critique 使用匹配的指令/计算对照；归属实验另做“角色 × 明示来源标签”的交叉设计。把 role/template 效应和作者归属效应分别报告。

### 2.4 Exp 3 的干预只能说明方向有作用，尚不能识别 authorship

位置：`research_design.md:46–49,104–114,185`。

删除 role tokens 或前五个内容 token，不能删除角色信息：后续内容 token 本来就能 attend 到角色前缀。由 assistant/user 差分得到的方向可能编码角色、位置、可信度、指令服从或修改倾向。随机方向控制只能排除部分一般扰动，不能排除这些具体解释。

H3b 的 null 也不能支持“任何因果 self-label 都不存在”；它至多说明指定层、方向和强度没有检测到效应。正结果首先证明该干预改变行为，不能直接上升为自我表征。中文文章 §一的字面“无来源标签”也应和“没有主体性自我”分开；前者需要面对 chat template 中显式角色标签的事实。

**建议：**加入同角色不同归属标签、同归属跨角色、等长包装、不同模板复现，以及一般纠错/拒答/流畅性控制。dev 上选定一个主设置；另外两个设置作为有校正的次要分析。明确定义干预发生在 prefill、decode 还是两者，KV cache 如何更新，以及 token span 如何跨模板对齐。Exp 4 的组件筛选也应在 dev 完成，或者明确作为探索性定位后再用独立样本确认。

### 2.5 Exp 5 同时操纵了更新、上下文可见性和训练目标

位置：`research_design.md:118–137`。

context arm 重新看到 a0 和 v，parameter arm 则从只有 q 的上下文作答。这可以比较两套完整方法，但不能把差异单独归因于 coupling type。还存在以下混杂：

- correct verdict 用完整 a0 的 NLL；incorrect verdict 只对答案 span 做 unlikelihood。两者目标、token 数和梯度性质不同。
- norm cap 是上限，不能保证各条件实现相同更新范数；LoRA 因子范数也不等于合成 ΔW 范数。
- external p=0.7 可能弱于 self-verdict，H4a 没有测定 self-verdict 的真实准确率、混淆矩阵和难度依赖。
- context spillover 设为零，是清除上下文且不改权重后的构造结果。它可用作隔离检查，不能作为理论的非平凡验证。
- self-prediction 提示本身改变任务/上下文；有限题目上的预测下降不能识别数学上的普遍不可预测性。

**建议：**至少增加“有无更新 × 是否保留同一反馈上下文”的 2×2 对照，报告整体方法效应与更新的增量效应。冻结 loss 公式、归一化、token mask、优化器、合成权重范数和 reset 规则；记录实际范数及 logit 改变量。加上 reliability-matched 的外部 verdict 对照，并保留准确率/混淆矩阵分析。H4b 的零 spillover 作为实现不变量；H4c/H4d 首轮作为探索性工作。

## 3. 统计与数据完整性

### 3.1 预注册、模型调参与划分存在时间顺序缺口

位置：`CLAUDE.md:19–20,72–79`；`research_design.md:71–74,126,165`。

- protocol 在 P1 汇报初始错误率、平衡数据，然后才划分 dev/test，却又禁止预注册前看到 test metrics。允许机器为分层生成标签和允许研究者看到哪些统计，需要明确区分。
- 仅在 1.7B pilot 后冻结，Exp 5 又要求 4B dev 确认学习率；必须放进 P3 之前，或预注册明确的适配算法及可选范围。
- 只说 item-level 不足以防止同一道原题的 clean/injected 版本、不同注入位置、不同模型版本、GSM8K 与 GSM8K-SC 等跨集合泄漏。
- probe 在 test 内做 grouped CV 不必然是泄漏：预注册的 cross-fitting 可以成立。但这时该集合不是所有预测器均未训练过的简单 holdout。每个样本必须用 out-of-fold 预测，标准化和校准也只能在训练折拟合，整个分析过程不得因 CV 结果再次调参。

**建议：**先按全局 canonical problem ID 分 train/dev/test；再在各 split 内生成版本和抽取自然错误。所有模型、数据变体沿用同一题目分组，显式做跨来源去重。为探针设置清晰的训练/验证/评估流程；若使用 cross-fitting，在预注册中写清目标、折分和 CI 处理。可以单独预注册数据构建规则，再冻结不看测试表现的最终分析计划。

### 3.2 平衡数据上的准确率不是原始任务总体准确率

位置：`research_design.md:71,94`。

选取全部错误加等量正确会人为设置初始正确率。净改善满足：

`Δacc = P(initial wrong) × W→R − P(initial right) × R→W`。

平衡样本对应两项权重均为 1/2，不能直接外推到原始 GSM8K/MATH 分布。模型各自筛出的错误集也不同，跨模型差异还包含题目构成差异。

**建议：**同时报告平衡诊断集效果和按预先规定的原始分布权重重加权的效果；给出来源分层结果。模型规模比较保留一个共同题目面板，不把不同错误集的数字直接当成 scale effect。

### 3.3 检验方法与独立单位没有完整定义

位置：`research_design.md:139–145`。

同题跨条件是重复测量。常规独立样本 Jonckheere–Terpstra 不适合直接使用；普通 logistic regression 也必须处理同题相关。正的线性斜率只说明总体趋势，不等于四个 p 水平逐一单调。verifier 的随机 mask 应在配对条件中复用，并预先规定跨 p 是否使用嵌套 mask、是否对多个 mask 复现。

H1a–c、H2a–b、H3b、H4a–c 是九个命名假设，但包含多个方向、模型、数据集及复合终点，不能只写一句 Holm 就定义好检验家族。H2a 需要配对 AUROC 差异的推断；H2b 需要冻结分位数参照集合；H4c 的独立更新轨迹只有两个 order seeds，多次 held-out 测量不能充当大量独立轨迹。

**建议：**为每个确认性假设列出主模型、主数据集、estimand、contrast、方向、检验、独立单位、缺失规则和所属 family。使用按题目分组的 bootstrap/permutation、适当的 GEE/mixed model；流实验以独立轨迹为更高层单位。两个 seed 下以描述性结论为主，不能将题目数量冒充轨迹重复次数。

### 3.4 F4 和 correctness scorer 还不能由文件直接实现

位置：`research_design.md:71–74,87,98–102`。

最终答案标签无法给出自然错误的“第一错误步骤”；最终答案正确也不保证整条推理无错。D-inj 的注入位置只是候选位置，还需确认原 trace 在此前正确。若让另一个 LLM 直接标注，就不能无条件称为 oracle。

此外，缺少答案提取、数学等价判定、单位/多答案、无法解析、截断、拒答和多个 final answer 的处理规则。verbal P(yes) 也必须定义 tokenization、大小写、空白、yes/no 概率归一化和 thinking 开关。直接取全词表中的单 token P(yes) 并用 0.5 阈值，可能把格式差异当成错误判断。

**建议：**首轮 F4 限定在具有可信逐步标注的注入子集，其他项目标为不可用并预注册排除规则。评分器用确定性算法和经核对的边界样例；失败输出按预定规则计分，不能静默丢弃。verbal verdict 可使用规范化的候选序列概率，并同时记录候选总概率质量。gold 信息只通过允许的 verdict/pointer 进入模型，不能进入生成 prompt 或 TTT loss。

## 4. 运行可行性与自主研究协议

### 4.1 Thinking 设置会引入额外失败

位置：`research_design.md:65,90–92`。

[Qwen3-4B 官方模型卡](https://huggingface.co/Qwen/Qwen3-4B)明确建议 thinking 模式使用采样，并警告 greedy 可能性能下降、反复循环。4096 tokens 可以作为预算限制，但必须统计截断率；不能将预算截断造成的无答案解释为纠错能力不足。thinking 开关也不等于从同一组权重中“移除 RL 训练影响”，它只是改变推理模式。

**建议：**主解码策略按模式分别冻结，并做配对种子；保留固定 token 预算及实际消耗统计。比较 thinking/non-thinking 时明确这是“推理模式与计算预算”的对比，不能识别 RL 训练的因果效应。

### 4.2 算力估算遗漏了大规模嵌套评估

位置：`research_design.md:133–159`；`CLAUDE.md:36–40,69–70,105–115`。

仅云端 300 items × 3 update conditions × 每次 50 个 spillover 项，就有 45,000 个题目级评分任务，尚未计入反向传播、重新生成、采样与其他对照。它们可以 batching，但不能在估时中当作 900 次普通推理。本地若为 400 items，同类计算是 60,000 个。两个数据集各 400 个测试题、20 条件的 Exp 1 已有 16,000 次生成，尚未加 sampled/thinking。

名义 4B bf16 权重本身约 7.45 GiB，12GB 卡上还需 KV cache、激活、反向传播、LoRA 和运行时空间。因此长序列梯度/patching 的可行性尚待实测，不能仅由“能加载模型”推出。P0 应在真实长度、batch、输出预算下量 peak VRAM 和时间，预定义 batch=1、checkpointing、分层缓存等策略。

按设计采用的 $3.49/h，3h 为 $10.47；$11 预算扣留 15% 后只剩约 2.68h GPU 时间，还未扣其他成本。协议中的 watchdog 公式约为 2.99h，与 15% 余量并不一致。当前 [JarvisLabs 官方价格页](https://jarvislabs.ai/pricing)仍列 H100 为该时价，并单列存储费；启动前仍应重新取价。停止进程/系统关机也必须与供应商停止计费动作区分，计费硬上限不能只依赖实例内一个进程。

**建议：**用“调用数 × 实测长度/速度 + 更新/评分/载入/传输成本”估算，明确预算是否包含存储与税费。云资源仅执行已通过本地验证的优先块；记录成本与样本数决定的停止原因，不将资源截断误写为科学 null。

### 4.3 当前目录还不是可直接启动的研究工程

位置：`CLAUDE.md:11–13,43–79`。

目录原先只有五个材料文件，实际 `research_design.md` 在根目录；协议却要求 `docs/research_design.md`。`theory/`、`STATUS.md`、运行代码与配置不存在，目录也不是 Git 仓库。这对方案草稿很正常，但自动研究必须明确 bootstrap 步骤。

P0 要求对“每个 module”smoke test，后续阶段才描述数据和实现，没有定义先实现什么。文中 pilot 的 Phase 3 称呼与 P2/P3 编号不一致。`CLOUD_LAUNCH=auto` 与“任何花钱行为都 stop”存在规则冲突；“contacts a third party”是否包括普通公开文献查询也应界定。全局失败重试与同一配置续跑没有区分，容易让 bug 修复后的结果覆盖旧结果或混入半旧半新 shard。

**建议给协议增加以下可验收内容：**

1. Bootstrap：确认根目录、初始化 Git、创建结构、索引理论材料、创建 STATUS；未满足条件时不启动 main runs。
2. 最小纵向实现：先跑通一题的 data → prompt → generation → scoring → report，再扩到每个实验；P0/P1 用独立的非测试 fixtures。
3. 版本清单：固定模型 revision、数据 revision、tokenizer/template hash、软件 lockfile、prompt hash、评分器 hash、配置 hash、代码 commit 和种子。
4. 冻结门槛：dev pilot、功效分析、评分器检查、prompt span 检查、无干预/零更新一致性检查全部通过后才可 freeze。freeze 后日志记录测试集首次访问时间。
5. 不变量检查：无干预 patch 应恢复 baseline；零 LoRA 应等价 baseline；reset 应恢复初始 logits；verifier mask 必须与 item ID 对齐；模拟 null/known effect 数据应得到预期统计结论。
6. 恢复规则：只有配置、代码、数据哈希一致时才能复用 shard。科学代码变更产生新 run ID，并将旧 run 标为 superseded，保留原始输出与修正原因。
7. 证据账本：每项主张连接到假设、分析脚本、结果表、适用范围、替代解释和允许的结论措辞。明确“得到反例/假设不成立”不是要求 AI 去修复的程序错误。
8. 自主性记录：记录每次人工介入的时间、触发原因和影响；记录模型/API 成本与 GPU 成本。完成实验块与得到正结果必须是两套状态。

原协议的五个人工核对示例是良好的起点，但不足以替代针对标签泄漏、数学判分和恢复一致性的测试。上述检查的目的不是测试文字是否符合模板，而是防止静默地产生错误科学结论。

## 5. 理论与引用核查

### 5.1 缺失 skeleton 是理论验证缺口

`CLAUDE.md:12` 把 skeleton 的缺失视为只影响写作，但 Exp 5 的 coupling 归类、H4d 和“必要条件”解释本身就依赖该文件。可以继续做与理论证明无关的 pilot，不能把相关定理当作已经核验。

两份 TXT 在陈述强度上也不完全一致：manifesto 有 candidate claim 和 future task，positioning note 则多处称为已证定理。还需统一状态/activation 是否足以算 Type-2、反身性必要条件与充分条件的差别，以及 closure 的稳定化性质是猜想还是已证明结果。

应要求形式化文件回答：

- 什么是数据端口、参数端口、自我模型，定义相对于哪一个固定系统边界？
- 将可变参数并入扩展状态后，系统同样可写成固定转移函数；为何这个重写不抹去所声称的区别？若区别是实现相对的，就明确如此，并限定允许的重参数化。
- `ρ: S → V^S` 的存在、其自我建模解释、完备性条件各如何建立？普通 context 条件化也可在数学上形成函数族，不能仅凭端口名称断言“无 ρ”。
- [Lawvere 原文](https://www.its.caltech.edu/~matilde/LawvereDiagonalArgCartesianClosedCats.pdf)的定理涉及特定范畴结构与弱点满射等条件。它不会直接给出 LoRA 后的平均预测准确率下降，也不会仅由“参数可写”推出时间错位是唯一解决方法。

此外，未给出 F、R 的条件时，闭合动力系统是否稳定、是否适定不能由“没有外部世界”独自决定。闭合系统可收敛到有用状态；外部信号也可 destabilize。相关文本需要将数学充分条件、经验倾向和研究猜想分开。

### 5.2 有一条已核实的引用存在可展示的数学问题

`research_design.md:27` 的 [Spectral Origins of the Self-Correction Blind Spot in Autoregressive Generation](https://arxiv.org/html/2607.09803v1)确实存在，但其 §3.5 Lemma 2 声称一般矩阵乘积满足 `ρ(J_T…J_1) ≤ ∏ρ(J_t)`。

本次独立反例为：

```text
A = [[1, 1],     B = [[1, 0],     AB = [[2, 1],
     [0, 1]]         [1, 1]]           [1, 1]]

ρ(A) = ρ(B) = 1
ρ(AB) = (3 + √5) / 2 ≈ 2.618 > 1
```

这些有限矩阵有界，乘积主特征值也是单根。该不等式不是一般有效的谱半径上界；通常可用的是范数乘积上界。这个反例足以要求作者为该引理添加实质性假设或修正论证。这里没有声称整篇论文所有结果都已被审计或推翻，但它不能未经数学检查就成为本项目的可靠理论前提。

因此协议中“每条引用有可打开 URL”只验证了书目存在。应增加 `supports_this_claim / domain_and_assumptions / limitations / proof_status` 等字段。

## 6. 建议的最小可行修订

先把第一阶段缩为一个可解释、统计上有承载力的研究问题：**固定模型和任务上，在控制提示格式与计算预算后，反馈可靠性与来源标签怎样改变纠错和误改。**

1. **确认性主线：Exp 1。** 以 4B 的预定模式为主，1.7B 用于开发；固定 feedback 格式和位置，预注册可靠性 contrasts、trigger controls、W→R/R→W 与总体净收益。只保留预算能够支撑功效的少数主检验。
2. **次要主线：Exp 2。** 检验预反馈 probe 与规范化 verbal verdict 的差异，控制题目难度、答案长度和任务来源；将 probe-confident-wrong 子组解释为可访问性分析。
3. **探索性机制：Exp 3/4。** 先验证行为效应稳定，再干预与 patching。若缺少足够的归属对照，就称为 role/template representation 干预。
4. **后续独立研究：Exp 5。** 补全更新/上下文交叉设计，先做小型 feasibility pilot；只有稳定且预算允许才扩展 streams。它比较反馈安装方法，不承担证明整个理论的任务。
5. **理论工作单独验收。** 补全 skeleton、定义与证明审查、隐藏状态玩具任务，并明确哪些结论属于定义、定理、经验预测或尚未验证的猜想。

最有价值的产出不应预先锁定为“支持理论的论文”，而应是可复现的数据、可解释的效应与局限、以及清楚说明哪些主张被支持、被反驳或仍无证据的报告。达到这些要求后，这两份 Markdown 才适合承担 autonomous research 的主要控制文档。
